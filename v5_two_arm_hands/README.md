# v5 — Stage 5：双臂 UR5e + LEAP 左右手（双球同步交换，三球 cascade 尝试）

两台 UR5e 并排，底座各垫高 0.4 m，都朝 +x；右臂（前缀 `r_`，LEAP 右手）在 y = −Y，左臂（`l_`，LEAP 左手）在 y = +Y。手法由一张通用的抛接事件表描述（每只手的出手时刻、抛向哪个接球点、接的是对方第几次抛出的球）。双球同步交换（S1）和三球 cascade 都只是不同的表。

## 文件

| 文件 | 内容 |
|---|---|
| `juggle.py` | 双臂抛接：手法（`sync2` / `cascade3`）、每只手的抛球标定、每只手一个状态机（搬运 → 等待 → 甩抛 → 从运动状态直接去接 → 接住后直接搬运），失败判定 |
| `results/` | 原始输出 |
| `../src/jugglebot/hands/` | 共享包（v4 的灵巧手代码，改为可区分左右手、支持多台手臂）：`model`（单臂 / 多臂模型组装、左右手镜像关系）、`handsim`（单臂规划模型：动力学、试抛）、`world`（多臂仿真）、`kinematics` / `prediction` / `planning`（v4 原样，`planning` 增加了 `next_weight`）、`throwing`（手型、手指时序、甩抛、标定） |
| `../assets/ur5e_leap_hands/` | `ur5e_leap_right.xml`（= v4 的 `ur5e_leap.xml`）、`ur5e_leap_left.xml`（左手）、`world.xml`（公共场景：地面、相机、材质） |
| `../assets/leap_hand/left_hand.xml` | Menagerie `leap_hand/left_hand.xml`（commit `0059d43`，与右手同一版本；`meshdir` 改为 `.`）；左手网格本来就在该目录 |

## 运行（在仓库根目录）

```bash

uv run python v5_two_arm_hands/juggle.py --pattern sync2 --F 0.5 --x0 0.85 --runs 1 --throws 8 --video videos/v5_sync2.mp4
```

## 左手

- Menagerie 的左手手掌坐标就是右手的镜像（y 取反）再加平移：p_left = diag(1, −1, 1)·p_right + (−0.0759, −0.0908, 0.026)（用 10 个手掌碰撞盒拟合，误差约 1 mm）。
- 屈曲关节（mcp / pip / dip、拇指 cmc / mcp / ipl）相同角度时指尖互为镜像（误差 0.5–1.8 mm）；外展关节 rot、th_axl 要取反号。所用手型里外展都是 0，所以 v4 的手型直接通用。
- 左手装在法兰上的位置按"关于 hand_mount 的 y = 0 平面与右手互为镜像"算出（`hand_offset` = (0.1219, −0.0548, −0.029)）。装上手臂后，平掌 / 握球 / 碗状三种手型下，指尖与镜像位置相差 ≤ 1.9 mm。
- v4 中以右手掌心坐标给出的量（`BALL_ON_PALM`、碗状球座）用同一关系换算（`model.palm_point`）。
- UR5e 本身不是镜像对称的（各连杆有侧向偏置），所以镜像的手位姿一般要用不同的关节角（6 维 IK）。在 `Q_READY` 下法兰正好位于底座的 xz 平面，左臂取相同关节角就是右臂的精确镜像（误差 1e-7），所以两臂都用 `Q_READY` 作零空间名义构型。代价是：同一个出手点，左右手的偏航角并不镜像（相差约 10°）。

## 布局

- 每台手臂在自己的底座坐标系中规划（单臂模型），世界坐标 = Rz(yaw)·p + 底座位置。
- `--toe-in`：底座向内转的角度。默认值使出手点正好在手臂正前方（像 v4 E5）。但这样一来，沿世界 y 方向的抛球在手臂坐标里多了一个向外的分量：3 m/s 的甩抛需要 > 0.9 × 180°/s。不内转、Y = 0.3 m（出手点在手臂坐标 y = ±0.2）时 3.0 m/s 可行（关节速度 0.88）。
- 底座不内转时，出手点在手臂坐标里离正前方超过约 0.25 m，3 m/s 的甩抛就超出关节速度裕量（Y = 0.35 / 0.45 m 时 cascade 的抛球标定失败）。

## 相对 v4 E5 的改动

| 改动 | 原因 |
|---|---|
| 碰到掌心 40 ms 后（手指已收紧）就从缓冲中的运动状态直接搬运，不先停下（`--grasp-delay`，`--no-early-carry` 恢复 E5 做法） | 省掉一次停—起 |
| 接球代价加上"接球位姿到下一次行程起点的关节距离"（`--next-weight`，默认 1） | 在能接到的前提下，选搬运短的接球点 |
| 搬运来不及时，这一抛最多推迟 40 ms（`--max-delay`）；推迟量同步给接球的那只手（平移它的先验出手时刻），它再按观测重规划 | 双臂时来球带着真实的出手误差，接球位置和时刻会变 |
| 两臂相碰（ARM_COLLISION）判失败 | |

## 结果

### 双球同步交换（`sync2`，`results/sync2_*.txt`，`videos/v5_sync2.mp4`）

设置：底座 y = ±0.35 m，内转 9.4°；F = 0.5 s；两条弹道前后错开 12 cm（x = 0.91 / 0.79 m）、左右在 y = ±0.2 m；两手同时出手。

| 周期 | 观测噪声 | 跑满（每手 20 次） | 接球 | 失败 |
|---|---|---|---|---|
| 1.2 s | 0 | 1/1（每手 6 次）、录像 1/1（每手 8 次） | 12、16 | — |
| 1.2 s | 5 mm | **4/5** | 166 | LATE 1（搬运迟到 43 ms，超过 40 ms 推迟上限） |
| 1.0 s | 5 mm | 0/5 | 10 | LATE 5（每次都在第一次接球后） |

周期 1.2 s 时：出手 2.6 m/s，E = 0.53 s，D = 0.67 s；离手速度误差均值 38 mm/s（最大 108），落到对方接球点偏 20 mm（最大 63）；25 次抛球推迟过（最多 38 ms）；关节速度峰值 0.90，手臂执行器力峰值 1.00。

**这就是项目的最低目标（双臂 + 双球抛接），在 180°/s 内达到。**

### 三球 cascade（`cascade3`，`results/cascade3_attempt.txt`，`videos/v5_cascade3_attempt.mp4`）

**还没有做成**：最好的配置（Y = 0.3 m，内转 14.5°，F = 0.57 s，τ = 0.345 s）连续接住 7 次后失败（LATE）。

| 现象 | 原因 |
|---|---|
| F = 0.6 s（E5 的值）时：不内转可以标定，但 τ ≥ 0.36 时左手的第一次接球规划不出；τ = 0.35 时搬运迟到 129 ms | 同一个对称布局下，右手在 τ = 0.36 能规划出第一次接球，左手不能：UR5e 不对称（两臂出手构型只差底座转角 0.48 rad，镜像动作并不是镜像的关节运动），加上左手约 10° 的偏航差 |
| 内转后 F = 0.6 s 的抛球不可行 | 抛球方向在手臂坐标里多了向外的分量 |
| F = 0.57 s 时 τ = 0.33–0.345 都在 4–7 次接球后 LATE | 2F 比 E5 少 5 %，窗口关闭：τ 大了 E 太短接不到，τ 小了 D 太短来不及搬运；对方的真实抛球误差使接球偶尔偏低，搬运就迟到 46–129 ms |

单臂 E5 的结论（窗口 τ ≈ 0.35–0.375 s、执行器力已到上限）在双臂里更紧：两只手都在真抛（没有理想的发射器），左右手又不对称。

## 局限 / 待办

- 三球 cascade：可能的方向见下（都需要讨论后决定）。
  1. 只放宽抛球行程的规划关节速度裕量（0.9 → 0.95 × 180°/s；硬约束 180°/s 不变），把 F 恢复到 0.6 s。
  2. 左臂换用另一个 IK 分支（肩部翻转），使它的运动学接近右臂的镜像，消除左右不对称。
  3. 缓冲 → 搬运 → 行程连成一条连续轨迹（行程不从静止开始），进一步压缩 D。
  4. 用节拍不固定的调度：按实际接球时刻调整之后的出手时刻。
- 左右手偏航不对称约 10°（两臂共用 `Q_READY` 作名义构型）。
- 手臂执行器力峰值 1.00（规划前馈 ≤ 0.9）。
- 同步交换的周期下限在 1.0–1.2 s 之间，未细扫。
